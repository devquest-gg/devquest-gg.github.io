Tap "Back to DevQuest" as if you finished applying.
WHEN IT FIRES

Only on return to the DevQuest tab after an apply click (or a fallback if the user never actually leaves). It is never between the user and a job posting — access to postings is completely untouched.

SAME CARD YOU ALREADY HAVE

This is your existing "Email me these roles" inline card and the same /subscribe backend — just triggered at a higher-intent moment and pre-filled from the job, so the only typing is the email.

NOT AN EXTRA NAG

It draws from the same one-ask budget as today (canAskEmail / luj-subscribed). If the user was already asked, dismissed, or subscribed, it stays silent. At most once per session; two dismissals snoozes it 30 days.

GENTLER FALLBACK

If even this feels like too much, the zero-result and Following prompts only appear when a user is already stuck or has opted in — zero risk to a happy browser. Reasonable to start there and compare conversion.

What to judge: does the card, appearing only after you've applied and returned, feel offered or naggy? Because it's inline (the jobs stay visible and scrollable behind it) and shares your existing quiet-window budget, it should read as "offered." If it crosses your line, we ship the Following + zero-result prompts instead and leave the apply flow completely alone.
