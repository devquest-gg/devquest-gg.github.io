Step 2 · If nothing fits, build from structured fields (not a text box)

Heads up: a very similar release already exists: Days Gone · PC (2020). Use that instead of making a near-duplicate? Use existing · create anyway
The canonical name and key are generated from the fields, so everyone who enters the same release lands on the same record. The collision check catches near-misses before they happen.
Step 3 · Provenance & cleanup
New release starts as community-added · unverified, and becomes established once a peer who worked on it vouches.
Duplicates that slip through are auto-flagged as look-alikes and can be merged, with reversible history. Same pattern MusicBrainz and Wikidata use.
Adding a whole new game (an unlisted indie, or a title too new for Wikidata) uses the same flow with a higher bar: search first, structured fields, community-added until vouched.
